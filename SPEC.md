# ccgauge — техническое задание, версия 1

Виджет для рабочего стола macOS, показывающий лимиты подписки Claude Code, заполнение окна контекста и прогноз исчерпания недельной квоты.

## Именование

| Где | Значение |
|---|---|
| Репозиторий, формула Homebrew | `ccgauge` |
| Отображаемое имя приложения | `Gauge for Claude Code` |
| Имя бандла в Finder | `CCGauge.app` |
| Bundle identifier | `dev.illvminat.ccgauge` |
| Bundle identifier расширения | `dev.illvminat.ccgauge.widget` — часть формата данных, см. 2.2 |
| Префикс типов в Swift | `CCGauge…` |

Разделение намеренное. `ccgauge` попадает в соглашение экосистемы (ccusage, ccstatusline, ccflare) и находится поиском. Отображаемое имя по формуле «X for Y» — описательное использование чужого товарного знака, которое Apple считает допустимым. Слово «Claude» не должно входить в имя бандла и идентификатор.

---

## 1. Зачем это нужно

Существующие инструменты (ClaudeBar, CCSeva, ClaudeUsageBar, ccusage) живут в строке меню или в терминале. Виджета на рабочем столе нет ни у кого. Прогноза исчерпания квоты нет ни у кого, включая встроенные команды `/context` и `/usage`.

Две эти вещи и есть причина существования проекта. Всё остальное — паритет с конкурентами.

**Целевой пользователь:** подписчик Claude Max или Pro на macOS, который упирается в недельный лимит и хочет видеть остаток без единого клика.

---

## 2. Ключевые архитектурные решения

### 2.1 Источник данных

Claude Code передаёт скрипту статуслайна JSON на stdin при каждой перерисовке. Схема проверена на версии 2.1.220, поля подтверждены живым снимком.

Доступно:

| Поле | Тип | Что даёт |
|---|---|---|
| `rate_limits.five_hour.used_percentage` | Int | Пятичасовое окно, % израсходовано |
| `rate_limits.five_hour.resets_at` | Int | Unix-время сброса, секунды |
| `rate_limits.seven_day.used_percentage` | Int | Недельное окно, % израсходовано |
| `rate_limits.seven_day.resets_at` | Int | Unix-время сброса, секунды |
| `context_window.used_percentage` | Int | Заполнение контекста, % |
| `context_window.total_input_tokens` | Int | Токенов в контексте |
| `context_window.context_window_size` | Int | Размер окна, обычно 200000 или 1000000 |
| `context_window.current_usage.cache_read_input_tokens` | Int | Прочитано из кеша |
| `context_window.current_usage.cache_creation_input_tokens` | Int | Записано в кеш |
| `cost.total_cost_usd` | Double | Стоимость сессии |
| `model.display_name` | String | Например `Opus 5 (1M context)` |
| `effort.level` | String | `low` / `medium` / `high` |
| `workspace.repo.name` | String | Имя репозитория |
| `workspace.current_dir` | String | Текущая папка |
| `session_id` | String | Идентификатор сессии |
| `version` | String | Версия Claude Code |

**Недоступно и добываться не будет:**

- Недельный лимит по конкретной модели (в JSON только два общих окна).
- Разбивка контекста по категориям (System tools, MCP tools, Skills и прочее) — это внутреннее представление команды `/context`.

**Проценты приходят не всегда целыми.** Столбец «Тип» выше описывает намерение, а не гарантию: живой снимок принёс `"used_percentage": 28.000000000000004`. Строгий разбор в `Int` на таком значении падает, и мягкий разбор из раздела 6 молча терял окно целиком — виджет рисовал прочерк при исправных данных. Поэтому экспортёр округляет проценты до целых на записи, а модель дополнительно умеет принять и дробное. Одной защиты мало: округление в экспортёре чинит данные, терпимость в модели — старые снимки и будущие сюрпризы.

**Важно:** блок `rate_limits` появляется только после первого ответа модели в сессии. Сразу после запуска или `/clear` его нет. Парсер обязан это переживать без падения — отсутствие полей штатная ситуация, а не ошибка.

### 2.2 Обмен через контейнер расширения

Расширения виджетов на macOS **всегда работают в песочнице**, независимо от того, в песочнице ли основное приложение. Прочитать `~/.claude/...` из виджета напрямую нельзя, поэтому нужна общая точка на диске.

Такой точкой служит **собственный контейнер расширения виджета**:

```
~/Library/Containers/dev.illvminat.ccgauge.widget/Data/Library/Application Support/ccgauge/
├── snapshot.json      # текущее состояние, перезаписывается
└── history.jsonl      # временной ряд для прогноза, дописывается
```

Расширение читает этот каталог как свой контейнер — доступ к нему песочница даёт всегда и безусловно, это и есть определение контейнера. Приложение и экспортёр обращаются к тому же каталогу по абсолютному пути: приложение не в песочнице, а экспортёр — обычный процесс пользователя.

**Путь вычисляется по-разному внутри песочницы и снаружи, и это обязательно.** Внутри песочницы домашний каталог процесса **и есть** его контейнер: `NSHomeDirectory()` возвращает `…/Containers/dev.illvminat.ccgauge.widget/Data`. Снаружи домашний каталог — обычный `/Users/имя`. Поэтому расширение достраивает к своему дому только `Library/Application Support/ccgauge`, а приложение и экспортёр — весь путь начиная с `Library/Containers`.

Соблазн написать одну формулу на всех приводит к удвоенному пути вида `…/Containers/…/Data/Library/Containers/…/Data/…`. Проверено на живом виджете: ошибка выглядит как «снимок не найден» и без лога неотличима от отсутствия данных.

#### Почему не App Group

App Group — очевидное и рекомендованное Apple решение этой задачи, и оно было реализовано первым. Оно не работает при ad-hoc подписи.

Проверено на живой системе: расширение виджета получает от `containermanagerd` путь к контейнеру группы (`container_create_or_lookup_app_group_path_by_app_group_identifier: success`), но ядро не выдаёт ему доступ — отказ `EPERM` и на чтение файла, и на листинг каталога. При этом обычное приложение в песочнице с теми же entitlements тот же контейнер читает без проблем. Разница именно в том, что расширение — не приложение.

Обзор сторонних виджетов на машине показал, что все работающие подписаны настоящей командой разработчика: три из четырёх используют идентификатор группы с префиксом Team ID, один — без префикса, но и он подписан командой.

Вывод: App Group для этого проекта означала бы обязательное платное членство в Apple Developer Program у **каждого, кто собирает из исходников**. Для инструмента, который ставится через Homebrew и правится желающими, это неприемлемая цена. App Group отвергнута.

Побочная выгода отказа: из entitlements ушло единственное ограниченное разрешение, и проект теперь собирается ad-hoc вообще без учётной записи разработчика — без `PROVISIONING_PROFILE_REQUIRED` и `PROVISIONING_PROFILE_SUPPORTED`. У расширения остаётся `com.apple.security.app-sandbox`, у приложения entitlements нет вовсе.

#### Принятые риски

**Запись в чужой контейнер не санкционирована Apple явно.** Каталог принадлежит расширению; то, что посторонний процесс пользователя может туда писать, — следствие обычных прав доступа, а не задокументированная гарантия. Apple вправе ужесточить это в любой версии macOS, например потребовав TCC-разрешения на `~/Library/Containers`. Риск принят сознательно: альтернатива — платное членство для всех, кто собирает проект.

**Путь завязан на bundle id расширения.** Смена `dev.illvminat.ccgauge.widget` меняет каталог и означает потерю накопленной истории, а с ней и прогноза, пока не наберётся новая. Идентификатор расширения следует считать частью формата данных и без нужды не трогать; при вынужденной смене историю надо переносить осознанно.

#### Порядок создания контейнера

Контейнер заводит система при первом запуске расширения. **Создавать его снаружи запрещено:** `containermanagerd` может счесть заранее созданный каталог чужим и увести его в сторону, после чего расширение окажется в другом месте, а экспортёр продолжит писать в пустоту.

Отсюда требование к установщику: перед подстановкой пути он **обязан проверить, что контейнер существует**, и при его отсутствии сказать прямо — «сначала добавьте виджет на рабочий стол, затем повторите настройку». Молча создавать каталог запрещено. Проверяется наличие `Data/Library/Application Support` внутри контейнера: этот подкаталог создаёт система, и по нему видно, что контейнер настоящий, а не чей-то самодельный.

Сам экспортёр несёт ту же защиту: если родительского каталога нет, он завершается, ничего не создавая. Подкаталог `ccgauge/` внутри уже существующего контейнера он создаёт сам — это часть контейнера, а не контейнер.

#### Как скрипт узнаёт путь

Экспортёр хранится в репозитории как шаблон `Scripts/ccgauge-export.py.template` с плейсхолдером `__GROUP_DIR__`. При установке приложение подставляет вычисленный путь и кладёт результат в `~/.claude/ccgauge-export.py`. Механизм подстановки не менялся с первой версии — сменилось только вычисляемое значение. Ручная установка тоже возможна: путь показывается на экране первого запуска.

### 2.3 Бюджет обновлений WidgetKit

WidgetKit жёстко ограничивает частоту перерисовки — порядка нескольких десятков обновлений в сутки на виджет. Наивная схема «перечитывать файл раз в 30 секунд» не заработает, система просто перестанет вызывать провайдер.

Правильная схема из двух механизмов:

1. **Предгенерация таймлайна.** Провайдер за один вызов отдаёт серию записей с шагом в одну минуту на ближайшие 30 минут. Все они построены из одного снимка, но с пересчитанным обратным отсчётом до сброса. Обратный отсчёт тикает без единого обращения к диску.
2. **Принудительная перезагрузка при изменении данных.** Демон, обнаружив новый снимок, вызывает `WidgetCenter.shared.reloadAllTimelines()`. Перезагрузки, инициированные приложением, тратят бюджет экономнее и дают мгновенную реакцию на реальное изменение.

Политика в конце таймлайна — `.after(последняя запись)`, чтобы система сама пришла за новой порцией.

### 2.4 Демон и честность данных

Данные приходят только когда работает Claude Code. Это фундаментальное ограничение выбранного источника, и его нельзя маскировать.

**Что демон делает в версии 1:**

- Следит за `snapshot.json` через `DispatchSource` по файловому дескриптору.
- При изменении дёргает перезагрузку виджета.
- Раз в минуту пересчитывает возраст снимка и обновляет признак свежести.
- Перезагружает таймлайны при запуске приложения.

**Дескриптор приходится переоткрывать.** Экспортёр пишет атомарно, через временный файл и `os.replace`, — значит на месте снимка каждый раз оказывается **новый inode** (проверено: номер меняется при каждой записи). Источник, привязанный к старому дескриптору, получает `.delete`/`.rename` и дальше молчит. Наблюдатель, написанный наивно, срабатывает ровно один раз, и это выглядит как «файл не меняется».

Отсюда две меры: на `.delete`/`.rename` дескриптор переоткрывается, и параллельно отслеживается сам каталог — он переживает подмену файла и ловит появление снимка, которого ещё нет.

**Перезагружать на каждую запись нельзя.** Статуслайн перерисовывается десятками раз в минуту, и прямое `reloadAllTimelines()` на каждое событие сожжёт бюджет из раздела 2.3 за часы. Поэтому перезагрузка идёт при выполнении обоих условий:

- изменилась **подпись** снимка — тройка процентов пятичасового окна, недельного окна и контекста. Возраст в подпись не входит: он меняется непрерывно, а отрисовывается предгенерированным таймлайном без участия демона;
- с прошлой перезагрузки прошло не меньше минуты.

События, попавшие в минутное окно, не копятся в очередь: следующая запись экспортёра разбудит демон снова. Отдельно от этого перезагрузка происходит при переходе свежести через порог — вид виджета меняется, а новых данных при этом нет и не будет.

**Перезагрузка при запуске приложения** нужна не только чтобы показать свежие цифры сразу. Она страхует случай, когда виджет простоял с устаревшим таймлайном, пока приложение было закрыто. Заменой перезапуска `chronod` при разработке она при этом **не служит** — см. раздел 5.1.

**Чего демон в версии 1 не делает:** не добывает свежие лимиты при закрытом Claude Code. ClaudeBar решает это запуском CLI и разбором вывода `/usage`. Механизм рабочий, но хрупкий и заслуживает отдельного исследования — вынесено в версию 1.1.

**Как честно показать возраст данных:**

| Возраст снимка | Поведение |
|---|---|
| менее 5 минут | обычный вид, подпись «только что» |
| 5–60 минут | подпись «N мин назад» |
| более 60 минут | цифры приглушаются до `secondary`, подпись «данные устарели» |
| более 24 часов | вместо цифр приглашение запустить Claude Code |

Виджет, который молча показывает вчерашние проценты — хуже отсутствующего виджета.

## 3. Скрипт-экспортёр

Заменяет собой скрипт-разведчик. Пишет два файла: снимок для виджета и строку в историю для прогноза.

Путь: `Scripts/ccgauge-export.py.template`, устанавливается в `~/.claude/ccgauge-export.py`.

В репозитории лежит шаблон, а не готовый скрипт. Плейсхолдер `__GROUP_DIR__` заменяется на реальный путь контейнера при установке — см. раздел 2.2, почему этот путь нельзя знать заранее.

Написан на чистом Python без обёртки на bash. Ранняя версия использовала heredoc внутри shell-скрипта и была сломана: два перенаправления в stdin подряд, побеждает последнее, Python получал данные вместо кода и молча завершался.

```python
#!/usr/bin/env python3
import json, sys, os, time

GROUP_DIR = "__GROUP_DIR__"

MIN_INTERVAL = 600  # см. раздел 7: дедупликация истории


def last_history_entry(path):
    """Последняя непустая строка истории. Читаем хвост, а не весь файл."""
    try:
        with open(path, "rb") as f:
            f.seek(0, os.SEEK_END)
            size = f.tell()
            f.seek(max(0, size - 4096))
            lines = f.read().splitlines()
        for raw in reversed(lines):
            if raw.strip():
                return json.loads(raw)
    except Exception:
        pass
    return None


def should_append(prev, entry):
    if prev is None:
        return True
    if prev.get("resetsAt") != entry["resetsAt"]:
        return True
    if prev.get("sevenDay") != entry["sevenDay"]:
        return True
    return entry["t"] - (prev.get("t") or 0) > MIN_INTERVAL


def main():
    try:
        d = json.loads(sys.stdin.read())
    except Exception:
        return

    os.makedirs(GROUP_DIR, exist_ok=True)

    rl = d.get("rate_limits") or {}
    cw = d.get("context_window") or {}
    cu = cw.get("current_usage") or {}
    ws = d.get("workspace") or {}
    repo = ws.get("repo") or {}
    md = d.get("model") or {}

    read = cu.get("cache_read_input_tokens") or 0
    write = cu.get("cache_creation_input_tokens") or 0
    total = read + write
    ratio = round(read / total, 4) if total else None

    def window(key):
        w = rl.get(key)
        if not w or w.get("used_percentage") is None:
            return None
        return {
            "usedPercentage": w.get("used_percentage"),
            "resetsAt": w.get("resets_at"),
        }

    snap = {
        "schemaVersion": 1,
        "capturedAt": int(time.time()),
        "sessionId": d.get("session_id"),
        "claudeCodeVersion": d.get("version"),
        "model": {
            "id": md.get("id"),
            "displayName": md.get("display_name"),
            "effort": (d.get("effort") or {}).get("level"),
        },
        "project": {
            "name": repo.get("name")
            or os.path.basename(ws.get("current_dir") or ""),
            "path": ws.get("current_dir"),
        },
        "limits": {
            "fiveHour": window("five_hour"),
            "sevenDay": window("seven_day"),
        },
        "context": {
            "usedPercentage": cw.get("used_percentage"),
            "totalInputTokens": cw.get("total_input_tokens"),
            "windowSize": cw.get("context_window_size"),
            "cacheHitRatio": ratio,
        },
        "cost": {"sessionUsd": (d.get("cost") or {}).get("total_cost_usd")},
    }

    tmp = os.path.join(GROUP_DIR, "snapshot.json.tmp")
    with open(tmp, "w") as f:
        json.dump(snap, f, ensure_ascii=False)
    os.replace(tmp, os.path.join(GROUP_DIR, "snapshot.json"))

    sd = snap["limits"]["sevenDay"]
    if sd:
        hist = os.path.join(GROUP_DIR, "history.jsonl")
        entry = {
            "t": snap["capturedAt"],
            "sevenDay": sd["usedPercentage"],
            "resetsAt": sd.get("resetsAt"),
        }
        if should_append(last_history_entry(hist), entry):
            with open(hist, "a") as f:
                f.write(json.dumps(entry) + "\n")

try:
    main()
except Exception:
    pass
```

Требования к скрипту:

- **Всегда завершается кодом 0.** Падение экспортёра не должно ломать интерфейс Claude Code.
- **Ничего не печатает в stdout.** Статуслайн остаётся пустым; виджет — единственный потребитель.
- **Пишет атомарно** через временный файл и `os.replace`. Иначе виджет однажды прочитает половину файла.
- **Отсутствие полей — норма.** Ни одно обращение к словарю не должно валиться на `KeyError`.

Подключение в `~/.claude/settings.json`:

```json
{
  "statusLine": {
    "type": "command",
    "command": "/Users/ИМЯ/.claude/ccgauge-export.sh",
    "padding": 0
  }
}
```

Тильда в пути не раскрывается — только абсолютный путь.

## 4. Схема снимка

```json
{
  "schemaVersion": 1,
  "capturedAt": 1785310000,
  "sessionId": "e9d4c9d7",
  "claudeCodeVersion": "2.1.220",
  "model": {
    "id": "claude-opus-5[1m]",
    "displayName": "Opus 5 (1M context)",
    "effort": "high"
  },
  "project": {
    "name": "example-app"
  },
  "limits": {
    "fiveHour": { "usedPercentage": 15, "resetsAt": 1785313200 },
    "sevenDay": { "usedPercentage": 61, "resetsAt": 1785376800 }
  },
  "context": {
    "usedPercentage": 5,
    "totalInputTokens": 50467,
    "windowSize": 1000000,
    "cacheHitRatio": 0.4088
  },
  "cost": { "sessionUsd": 0.311 }
}
```

Поле `schemaVersion` обязательно. Когда Anthropic поменяет схему статуслайна — а она поменяется — приложение должно уметь отличить старый снимок от нового и не рисовать чушь.

### 5.1 Переустановка при разработке

Ставить сборку следует через `Scripts/reinstall.sh`, а не руками. Последний шаг скрипта — **`killall chronod`, и он обязателен.**

Демон виджетов держит расширение загруженным и переживает подмену бандла: после копирования новой сборки он продолжает исполнять прежний код. Правки при этом выглядят неприменившимися — виджет рисует старое, логи содержат сообщения, которых в новых исходниках уже нет. Проверено на живой системе: расширение успевает подняться из наполовину скопированного бандла и потом крутит его до перезапуска демона.

`chronod` перезапускается системой сам через секунды, все виджеты перерисовываются. Отдельно отметим: перезагрузка таймлайнов из приложения (`reloadAllTimelines()`) эту проблему **не** решает — она заставляет старый код построить новый таймлайн, но кодом он остаётся старым.

Порядок в скрипте важен: остановить процессы → подменить бандл → запустить приложение (регистрирует расширение) → перезапустить демон.

## 6. Модели данных

```swift
struct Snapshot: Codable, Sendable {
    let schemaVersion: Int
    let capturedAt: Date
    let sessionId: String?
    let claudeCodeVersion: String?
    let model: ModelInfo?
    let project: ProjectInfo?
    let limits: Limits
    let context: ContextInfo?
    let cost: CostInfo?
}

struct Limits: Codable, Sendable {
    let fiveHour: LimitWindow?
    let sevenDay: LimitWindow?
}

struct LimitWindow: Codable, Sendable {
    let usedPercentage: Int
    let resetsAt: Date

    var remainingPercentage: Int { 100 - usedPercentage }
}
```

`capturedAt` и `resetsAt` декодируются из unix-времени через `.secondsSince1970` в `JSONDecoder.dateDecodingStrategy`.

**Почему `LimitWindow`, а не `Window`.** Короткое имя сталкивается со сценой `SwiftUI.Window` и требует полного имени в каждом файле с интерфейсом. Приставка снимает конфликт раз и навсегда.

**Все поля кроме `schemaVersion`, `capturedAt` и `limits` опциональны.** Это не перестраховка: `rate_limits` реально отсутствует в первые секунды сессии.

**Разбор `Limits` мягкий и это норма.** Поля внутри `LimitWindow` объявлены обязательными, но `resets_at` может прийти `null` — тогда строгий разбор уронил бы весь снимок из-за одного испорченного окна. Поэтому `Limits` имеет собственный `init(from:)`, где каждое окно разбирается через `try?`:

```swift
public init(from decoder: Decoder) throws {
    let c = try decoder.container(keyedBy: CodingKeys.self)
    fiveHour = try? c.decodeIfPresent(LimitWindow.self, forKey: .fiveHour)
    sevenDay = try? c.decodeIfPresent(LimitWindow.self, forKey: .sevenDay)
}
```

Битое окно даёт `nil` и рисуется прочерком, соседнее окно и весь остальной снимок выживают. Это то же требование мягкого разбора, что и в разделе 14, применённое на уровне модели.

### 6.1 Мягкий разбор обязан быть громким

**Правило: молчаливое проглатывание запрещено.** Каждое срабатывание `try?` при разборе сопровождается двумя записями — в системный лог и в диагностику снимка. Мягкий разбор без этого превращается в тихую потерю данных: поле исчезает, виджет рисует прочерк, и настоящая причина ищется вслепую.

Правило появилось не из принципа. Живой снимок принёс дробный процент (раздел 2.1), мягкий разбор отработал как задумано и отбросил всё пятичасовое окно целиком. Виджет показал прочерк при исправных данных, и на поиск причины ушло время, которого одна строка в логе стоила бы дешевле.

**Три обязательных места:**

1. **Лог.** `os.Logger`, подсистема `dev.illvminat.ccgauge`, категория `parsing`, уровень `error`. В сообщении — имя поля, сырое значение из JSON и причина отказа. Сырое значение снимается отдельным разбором в `JSONValue`: без него в логе остаётся «поле не разобралось», что бесполезно.
2. **Поле `diagnostics` в `Snapshot`.** Список `ParseIssue` — поле, сырое значение, причина. В норме пустой. Собирается при декодировании через `DiagnosticsCollector` в `userInfo` декодера и в JSON не хранится: это свойство разбора, а не данных.
3. **Окно приложения.** Если список непуст, показывается блок с перечнем отброшенных полей. Единственное место, где разработчик увидит проблему, не открывая Console.app.

Единственное исключение — отсутствующее поле. `rate_limits` в первые секунды сессии нет штатно, и шуметь об этом не надо. Отличие принципиальное: **нет поля — молчим, поле есть и не разобралось — кричим.**

## 7. Прогноз

Единственная функция, которой нет ни у одного конкурента. Ей стоит уделить время.

**Вход:** `history.jsonl`, отфильтрованный по текущему недельному окну (записи, у которых `resetsAt` совпадает с актуальным).

**Алгоритм:**

1. Отбросить записи старше текущего окна — при сбросе процент падает скачком, и регрессия по смешанным окнам даст мусор.
2. Если точек меньше 5 или разброс по времени меньше 30 минут — прогноз не строить, показать прочерк. Врать хуже, чем молчать.
3. Линейная регрессия методом наименьших квадратов: `usedPercentage` от времени.
4. Если наклон не положительный — расход стоит, прогноза нет.
5. Экстраполировать до 100%, получить момент `t₁₀₀`.
6. Сравнить с `resetsAt`:
   - `t₁₀₀ > resetsAt` → укладываешься, линия жёлтая, подпись «хватит до сброса»
   - `t₁₀₀ ≤ resetsAt` → не укладываешься, линия красная пунктирная, подпись с датой и временем

**Дедупликация при записи.** Статуслайн перерисовывается на каждый чих — замеры дали пятнадцать вызовов за две с половиной минуты, все с одним и тем же процентом. Писать каждый вызов бессмысленно: порог усечения пробивается за пару часов работы, а полезных точек в файле не прибавляется.

Правило: новая строка пишется, только если выполнено хотя бы одно условие —

- `sevenDay.usedPercentage` отличается от последней записи;
- с момента последней записи прошло более 10 минут;
- последней записи нет либо у неё другой `resetsAt` (сменилось окно).

Десятиминутная отсечка нужна, чтобы регрессия видела ровное плато, а не разрыв: без неё период простоя выглядел бы как отсутствие данных, а не как нулевой расход.

**Усечение истории:** держать не более 2000 строк, при превышении переписывать файл, оставляя последние 1000. Иначе за месяц файл вырастет до неприличного размера, а виджет обязан читать его быстро.

**Сглаживание:** взвешивать точки по свежести (экспоненциально), чтобы вчерашний марафон не портил сегодняшний прогноз.

## 8. Пороги и цвета

```swift
enum Level { case healthy, warning, critical, depleted }
```

**Все три величины показываются как израсходованное.** Это правило, а не деталь вёрстки: в одном столбце не должно стоять двух противоположных вещей. Раньше лимиты показывали остаток, а контекст — заполнение, и в соседних строках «больше» означало то «лучше», то «хуже». Читать такое можно только с оговоркой, а оговорку виджет сообщить не успевает.

Заодно это выравнивает нас с официальной панелью Usage в приложении Claude, которая тоже показывает израсходованное, — см. 8.1.

**Лимиты — от расхода:**

| Израсходовано | Уровень | Цвет |
|---|---|---|
| < 50% | healthy | зелёный |
| 50–80% | warning | жёлтый |
| 81–99% | critical | красный |
| 100% | depleted | серый |

**Контекст — от расхода, пороги строже:**

| Израсходовано | Уровень | Цвет |
|---|---|---|
| < 50% | healthy | зелёный |
| 50–70% | warning | жёлтый |
| > 70% | critical | красный |

Полярность теперь общая, разными остались только допуски. Контекст переходит в красное на 70%, лимит — на 81%: выше 70% модель начинает хуже удерживать детали из начала диалога, а лимит по-настоящему опасен лишь у самого исчерпания.

**Пороги лимитов — та же граница, что и в прежней редакции**, переписанная от расхода: «остаток > 50 / 20–50 / 1–20 / 0» даёт в точности «расход < 50 / 50–80 / 81–99 / 100». Смена полярности не должна была поменять цвета местами, и не поменяла.

**Полоска всегда равна показанному числу и заполняется по мере расхода.** Раньше у лимитов она опустошалась. Полоска, растущая в одной строке и убывающая в соседней, — тот же дефект, что и смешанные величины, только в графике.

**Подписи обязаны называть величину.** «Week used», «Context used», «used · resets Чт 07:00». Полярность должна читаться с виджета, а не выводиться из знания о том, как он устроен.

Конкретные значения цветов брать из системных `Color.green` / `.yellow` / `.red` — они сами адаптируются к светлой и тёмной теме и к настройкам доступности. Свою палитру заводить не нужно.

**Доступность:** цвет не должен быть единственным носителем смысла. Уровень дублируется формой индикатора либо подписью — иначе виджет бесполезен при дальтонизме.

### 8.1 Сверка с панелью Usage

Единственный доступный способ проверить, что виджет не врёт, — сличить его цифры с панелью Usage в приложении Claude. Другого независимого источника у нас нет: `rate_limits` недокументирован (раздел 14), и ошибка в нашей арифметике внешне неотличима от правильного ответа.

**Поэтому сверка обязана быть проверкой в одно действие.** Панель Usage показывает израсходованное; виджет теперь тоже. Числа должны совпадать **напрямую, без вычитания из ста**. Расхождение сразу означает ошибку — в разборе, в округлении или в выборе окна, — а не «так и должно быть, у нас же остаток».

Прежняя редакция требовала считать в уме: панель говорит 64%, виджет показывал 36%, и совпадение подтверждалось сложением. Такая сверка не делается мимоходом, а значит не делается вовсе.

**Подписи в панели и в виджете не совпадают дословно**, поэтому соответствие фиксируется здесь целиком. Без этой таблицы человек, сверяющий цифры впервые, потратит минуту на догадки — ровно то, чего раздел и должен избежать.

| Строка виджета | Панель Usage | Сверяется |
|---|---|---|
| `5-hour used` | **Current session** | да, число в число |
| `Week used` | **All models** | да, число в число |
| `Context used` | — | нет: это заполнение окна контекста, а не лимит подписки |
| — | **Fable** | нет: в JSON статуслайна нет разбивки по моделям (раздел 2.1) |

Два разночтения в названиях стоят того, чтобы их проговорить.

**«Current session» — это пятичасовое окно аккаунта, а не сессия диалога.** Терминология Anthropic, и именно из-за неё строка виджета называется `5-hour`, а не `Session`: рядом в подвале стоит `this session` про стоимость, и там слово означает уже сессию Claude Code. Одно слово в двух значениях — источник ошибок при сверке.

**«All models» — это недельное окно**, общее по всем моделям. Отдельная строка **Fable** в панели показывает недельный лимит по конкретной модели; в статуслайне такого поля нет и не будет (раздел 2.1), поэтому в виджете её нет. Отсутствие строки — не дефект, и сверять её не с чем.

Контекст и стоимость в панели Usage не показываются вовсе. Это отдельная причина не смешивать их с лимитами в одном столбце разной полярности: у половины строк есть внешний эталон, у половины нет, и различать их надо с одного взгляда.

Расхождение в один процент допустимо: экспортёр округляет дробные значения (раздел 2.1), панель может округлять иначе. Расхождение больше единицы — дефект.

### systemMedium (338×158)

- Шапка: модель и уровень усилий
- Три строки-полоски: `5-hour used`, `Week used`, `Context used`. У каждой подпись, полоска, процент, вспомогательное значение

Одно слово в двух значениях по соседству — источник ровно той путаницы, которую снимает подпись `this session` в подвале.

## 10. Локализация

Механизм: String Catalogs (`.xcstrings`), по одному на таргет.

**Основной язык — английский.** Русский равноправный перевод, не источник.

Стартовый набор: `en`, `ru`, `ja`, `zh-Hans`, `es`, `de`.

Даты, время, проценты и разделители разрядов форматировать **только** через `Date.FormatStyle`, `Measurement` и `NumberFormatter` с системной локалью. Никакой ручной склейки строк вида `"\(hours)ч \(minutes)м"` — в японском и немецком это выглядит неправильно.

Относительное время («2 минуты назад») — через `RelativeDateTimeFormatter`, он локализован из коробки.

Отдельного внимания требует плюрализация в русском: 1 минута, 2 минуты, 5 минут. В String Catalogs для этого есть варианты по правилу множественного числа — заполнить их, а не игнорировать.

## 11. Первый запуск

Самое слабое место продукта: виджет не заработает, пока пользователь не пропишет строку в конфиге Claude Code. Экран первого запуска должен вести за руку.

Три шага:

1. **Проверка.** Приложение ищет `~/.claude/settings.json`. Найден — показывает, что Claude Code обнаружен. Не найден — объясняет, что нужен Claude Code, со ссылкой.
2. **Установка.** Кнопка «Настроить автоматически»: приложение делает резервную копию `settings.json`, подставляет путь контейнера вместо `__GROUP_DIR__` в шаблоне экспортёра, кладёт результат в `~/.claude/ccgauge-export.py`, выставляет права на исполнение и дописывает ключ `statusLine`. Рядом кнопка «Показать инструкцию вручную» с командой в буфер обмена — для тех, кто не хочет пускать приложение в свои конфиги. Путь контейнера показывается на экране, чтобы подстановку можно было сделать руками.
3. **Ожидание.** Экран с крутящимся индикатором и текстом «Запустите Claude Code и отправьте любое сообщение». Приложение следит за появлением `snapshot.json` и при успехе показывает первые живые цифры с кнопкой «Добавить виджет».

Существующий ключ `statusLine` нельзя молча затирать — если там что-то есть, спросить и предложить резервную копию.

## 12. Порядок работ

Этапы упорядочены так, чтобы после каждого было что-то работающее и проверяемое.

**Этап 1 — данные.** Скрипт-экспортёр, папка App Group, модели `Snapshot`, чтение из `SnapshotStore`. Проверка: консольная утилита печатает разобранный снимок.

**Этап 2 — виджет-минимум.** Таргет расширения, App Group в capabilities обоих таргетов, `TimelineProvider`, только `systemMedium`. Проверка: виджет на рабочем столе показывает живые цифры и обновляется.

**Этап 3 — остальные размеры.** `systemSmall` и `systemLarge` без прогноза, полировка вёрстки, тёмная тема.

**Этап 4 — прогноз.** `HistoryStore`, усечение, регрессия, график в большом размере.

**Этап 5 — демон и свежесть.** `SnapshotWatcher`, принудительная перезагрузка, деградация при устаревании данных.

**Этап 6 — первый запуск и локализация.** Онбординг, шесть языков, проверка вёрстки на немецком и японском.

**Этап 7 — выпуск.** README со скриншотами, сборка релиза, формула для Homebrew, публикация.

Этапы 1 и 2 — это и есть «виджет за вечер». Остальное наращивается.

## 13. Чего в первой версии не будет

Зафиксировано сознательно, чтобы не расползлось:

- **Снимок на сессию и настраиваемый виджет.** Экспортёр глобальный: все сессии Claude Code пишут в один `snapshot.json`, побеждает последняя отрисовавшаяся. Лимиты и прогноз от этого не страдают — они общие для аккаунта. Контекст, стоимость, доля кеша и имя проекта посессионные и мигают между сессиями; в первой версии это принято и честно подписано (проект у строки контекста, `this session` в подвале).

  Полное решение — хранить снимок на сессию — само по себе мигание не лечит: «последняя активная» ведёт себя так же. Смысл оно приобретает только вместе с настраиваемым виджетом на `AppIntentConfiguration`, приколоченным к выбранному проекту. **Обе фичи идут вместе во второй версии, порознь не имеют смысла.**

  Показ всех активных сессий в большом размере — не раньше посессионного хранения и **не ценой прогноза**: место в большом размере занято прогнозом, а он и есть главное отличие продукта.

- Мультипровайдер. Codex, Gemini и Copilot дают расход в токенах, но не квоты плана — это другой тип данных и другой интерфейс. Версия 2.
- Недельный лимит по конкретной модели. В статуслайне его нет.
- Разбивка контекста по категориям. Требует разбора файла транскрипта, отдельная большая работа.
- Уведомления. Их закрывает ClaudeBar, дублировать в первой версии незачем.
- Сборка под Mac App Store. Возвращаемся к ней, если проект наберёт пользователей.
- Автообновление через Sparkle. Достаточно Homebrew.

## 14. Открытые вопросы

**Только терминальный Claude Code.** `statusLine` вызывается лишь в терминальной версии. У пользователя десктопного приложения экспортёр не запустится никогда, и виджет останется пустым навсегда — не «данные устарели», а вообще без единой цифры. Это отсекает часть аудитории, и умолчать об этом нельзя: **в README ограничение должно стоять в первом абзаце, до инструкции по установке.** Снимается решением вопроса о фоновом опросе лимитов — что поднимает приоритет того вопроса выше, чем предполагалось изначально.

**Свежесть при закрытом Claude Code.** Единственная нерешённая проблема архитектуры. Требует исследования: можно ли получить лимиты без интерактивной сессии. Кандидаты — разбор кеша в `~/.claude`, headless-режим CLI, наблюдение за файлами транскриптов. До решения виджет честно показывает возраст данных.

**Стабильность схемы статуслайна.** Формат недокументирован в части `rate_limits` и может измениться в любом выпуске Claude Code. Смягчение: `schemaVersion`, мягкий разбор, понятное сообщение вместо падения.

**Риск дублирования со стороны Anthropic.** В трекере Claude Code уже открыт запрос на индикатор контекста в десктопном приложении. Если его реализуют, часть ценности проекта исчезнет. Это аргумент за быстрый выпуск и за то, чтобы делать ставку на прогноз — его вряд ли добавят.
